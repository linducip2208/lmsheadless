# PWA

All five frontends ship `manifest.webmanifest` (standalone, theme colors,
192/512/maskable PNG + SVG icons generated by `scripts/generate-icons.mjs`),
a versioned `sw.js`, and `offline.html`.

## Cache strategy

- App shell (`/`, `index.html`, manifest, icons): precached on install.
- `/assets/*`, `/icons/*`: cache-first.
- Navigations: network-first → shell cache → offline page.
- API: **only** explicitly public GETs are cached stale-while-revalidate:
  `openapi.json`, `*/branding`, `certificates/verify/*`, `push/config`.
  Everything else (especially grades, submissions, tokens) is network-only.
  Writes are never cached and always go to network.
- Version bump in `sw.js` + `SKIP_WAITING` + `controllerchange` reload +
  update toast (`bindSwUpdates()` in `@lms/ui`).

## Offline behavior (honest)

The student portal shows cached shell + an offline indicator. Lesson
completions queue in `localStorage` and flush with `Idempotency-Key` when back
online (no duplicate writes; max 5 attempts, then kept for manual retry).
We do **not** claim full offline learning: quizzes and submissions require
connectivity.

## Push

`POST /api/v1/push/subscriptions` + `GET /api/v1/push/config` + service-worker
`push` handler + `subscribePush()` helper. Delivery requires a VAPID key in
settings; without it the UI says so plainly.
